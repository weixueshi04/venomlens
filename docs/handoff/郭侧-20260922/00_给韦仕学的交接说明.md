## 3. 韦先这样跑（Windows + Git Bash）

解压到新目录，打开包含本文件、`inference/`、`contracts/`、`data/` 的目录作为工作目录，保留相对结构。文档里的 `E:\BoldMaker` 是郭原工程根目录，在本机操作时替换为解压目录；不要把整个包直接覆盖到已有 Android 工程。

使用 Python 3.12。若尚无合适环境，执行一次（安装依赖需要访问包源，但不调用识别供应商）：

```bash
python -m venv .venv
source .venv/Scripts/activate
python -m pip install -r inference/requirements.txt
```

已有可用环境则直接激活，运行离线回归：

```bash
RECOGNITION_MODE=mock LIVE_CALL_LIMIT=0 HHODATA_API_KEY= HHODATA_CLASS=R PROXY_TOKEN= PYTHONDONTWRITEBYTECODE=1 PYTHONIOENCODING=utf-8 python -B -m unittest discover -s inference/tests -v
```

预期 `Ran 48 tests`、`OK`。预算用例只使用临时 SQLite，供应商用例使用假 Adapter／MockTransport。当前依赖会出现 Starlette/HTTPX 弃用提示；畸形表单用例也会输出解析提示，这两项不表示测试失败，不必为消除提示临时升级依赖。

在这个终端启动本机模拟代理：

```bash
RECOGNITION_MODE=mock LIVE_CALL_LIMIT=0 HHODATA_API_KEY= HHODATA_CLASS=R PROXY_TOKEN= python -B -m uvicorn inference.app:app --host 127.0.0.1 --port 8765
```

另开终端，在同一解压目录、同一 Python 环境下执行：

```bash
curl --noproxy '*' --fail-with-body http://127.0.0.1:8765/healthz
```

预期 `status=ok`、`mode=mock`、`localCallLimit=0`、`localCallsUsed=0`。这里的 0 是新模拟实例的状态，**不是郭正式账本清零，也不是供应商余额**。本机可查看 `http://127.0.0.1:8765/docs`；用完 Ctrl+C 停止代理。

### 用合成图片演示请求

包内不带原始照片；下列命令生成一张纯色 JPEG，仅用于验证输入格式和 HTTP 流程，没有蛇，也不是模型识别证据：

```bash
python -c "from PIL import Image; Image.new('RGB', (64, 64), 'gray').save('mock-input.jpg')"
curl --noproxy '*' -i http://127.0.0.1:8765/v1/recognitions \
  -H 'X-Mock-Scenario: candidates' \
  -F 'requestId=wei-mock-001' \
  -F 'uploadConsent=false' \
  -F 'image=@mock-input.jpg;type=image/jpeg'
```

按契约第 5 节逐一替换 `X-Mock-Scenario`，验证 7 个场景。纯色图在 mock 下返回候选是固定响应的预期行为，界面必须标注模拟。

演示手动查询时，先将场景改为 `pending`，从响应取得 `recognitionId`，再手动执行以下命令；将占位文字替换为刚返回的实际标识：

```bash
curl --noproxy '*' -i 'http://127.0.0.1:8765/v1/recognitions/替换为返回的recognitionId/refresh' \
  -H 'Content-Type: application/json' \
  -H 'X-Mock-Scenario: candidates' \
  --data '{"requestId":"wei-query-001"}'
```

该过程只是模拟 pending → candidates，不会创建供应商任务。真实模式不允许发送 `X-Mock-Scenario`。

**完成标准：**健康检查符合上述值，7 个场景状态码符合契约，pending 可经一次显式查询演示完成；界面正确显示模拟来源。

## 4. Android 接入顺序与验收

1. 先用包内 fixtures 开发识别状态页面，再接本机／受控局域网 mock 代理；郭不改韦的 Android／相机代码。
2. 按契约实现 multipart 上传、响应解析、待处理页面与手动查询按钮；不要添加自动查询计时器或网络库自动重试。
3. 用下面清单验收，再与郭约定真实联调的图片、上传同意和最大外发次数。

- [ ] 7 种模拟结果全部能显示；`requestId` 不属于当前采集时不覆盖当前页面。
- [ ] `uncertain` 即使有候选也能显示候选，同时保留不确定提示。
- [ ] 明确区分 `mock`、`live`、`cache`；不把缓存耗时当作当次识别耗时。
- [ ] 图片大小／格式错误、鉴权失败、未同意上传、额度不足等按契约处理。
- [ ] `score=null`、原始 `providerScore` 和缺失参考图不会造成界面崩溃；不显示“97.6% 准确率”。
- [ ] pending、超时、无蛇和未知均不阻断伤情记录、信息卡和求助入口；未知风险不显示为无毒／安全。
- [ ] 真机拍摄、取图与相机 Wi-Fi 下的网络行为另行实际验证，不用电脑回归替代。

`127.0.0.1` 只服务当前电脑，真机上的同一地址指向手机自身。需要手机访问代理时，先约定受控局域网地址、代理凭证、防火墙及 Android 开发环境网络配置，再调整监听地址；本包没有替韦修改这些设置，也没有公网服务地址。使用 fixtures 开发页面可先避开网络阻塞。

## 5. 颈棱蛇与旧缓存：容易误解的地方

- 首次实测时映射尚未补齐，因此正式旧缓存是 `uncertain`、空候选。
- 本次物种表已补齐颈棱蛇；用保存下来的供应商响应离线重放，能得到颈棱蛇候选。第二候选 `Daboia mauritanica` 尚未映射，所以完整响应仍为 `uncertain`，并非映射失效。
- 可单独运行已记录响应回归，验证数据映射而不重新上传：

```bash
RECOGNITION_MODE=mock LIVE_CALL_LIMIT=0 HHODATA_API_KEY= PROXY_TOKEN= python -B -m unittest inference.tests.test_app.AppTests.test_recorded_keelback_result_maps_and_replays_without_more_calls -v
```

- 该用例通过 MockTransport 回放；其中 `live` 是被测代码路径的输出，不是本轮真的访问了供应商，不应当作新识别证据。
- 正式旧缓存只存转换后的结果，不随物种表自动重算。保留原账本，不通过删除、换路径、修改图片或重新上传来刷新展示。
- 颈棱蛇只核验名称；风险为 `unknown`、参考图为 `null`。玉米蛇与加州王蛇仍为 `pending_review`，只是 mock 开发条目。
