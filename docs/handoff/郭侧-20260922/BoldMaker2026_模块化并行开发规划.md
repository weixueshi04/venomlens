## 1. 核心建议

**郭浩天负责「图片进去、可信格式的识别结果出来」；韦仕学负责「相机影像进去、可交给医生的信息卡出来」。先固定 Interface（接口约定），再分别开发，首晚争取完成一次受预算约束的真实联调。**

不要让韦仕学等模型接通，也不要让郭浩天等相机接通：双方先用固定模拟响应和离线测试并行开发；真实识别仅在参数、样本用途及调用预算确认后进行。

## 2. 范围：先交付什么，明确不做什么

### P0：必须交付的演示闭环

演示前置条件：App 已打开并保持前台、相机已连接、必要权限已确认；本轮不承诺手机锁屏后仍能自动唤起完整流程。

1. 影石相机影像进入 Android App；首选验证原定「相机按键 → 数秒录像 → 取帧」链路。
2. 提交图片识别，返回最多 3 个候选，支持「未检出蛇」「无法判断」与请求失败。
3. 用户选择「未被咬伤／被咬伤」，**无论识别是否完成，都能直接进入伤情记录与求助入口**。
4. 未被咬伤：提示保持距离，展示候选及经整理的科普信息。
5. 被咬伤：生成本地病例信息卡，包含原图、AI 候选与不确定性、参考图（有合规素材时）、伤情、时间及位置；不等待所有字段填完。
6. 显示医院名称、地址、电话、数据来源和核验日期，支持复制及打开拨号界面。
7. 原图、伤情与位置默认留在手机；云端识别前单独征得图片上传同意。

### P1：仅在 P0 全部跑通后做

- 病例卡图片分享／导出、更多标准参考图、定位后的距离排序。
- 若已验证普通拍照链路，再完善数秒录像自动截帧、多帧优选。
- 测试记录、用 Demo 拍摄至少 6 张照片的加分材料，应在稳定后优先于新增花哨功能。

### 本轮不做

- 相机固件改造、相机端 AI、自训练分割／分类网络、多模型同时上线。
- 独立分割流水线、全景识别优化、持续后台自动监测、锁屏唤醒保障。
- 医院系统对接、实时血清库存、自动诊断、抗蛇毒血清用药推荐。
- 用户账户、云病例数据库、用户影像上传社区、区域蛇类分布预警、环境预判。
- 离线识别。断网仍能查看本地病例卡／医院资料，不等于支持离线 AI。

**降级不伪装完成：**若相机物理快捷键无法在时限内接入，可以先交付 App 按钮控制相机拍摄；若传输仍阻塞，可用已拍影石素材导入验证流程。两者均须在 PPT 和视频标明与原目标的差距，由队长确认，不声称实现了相机一键全自动。

## 3. 模块划分与唯一负责人

采用 **一个 Android 工程 + 一个轻量推理代理**；Android 内以包划分 Module，不为每个 Module 新建 Gradle 工程或独立部署。

| Module | 唯一负责人 | 对外 Interface / 产物 | 隐藏在 Implementation 内的复杂度 | 独立验收方式 |
|---|---|---|---|---|
| M0 协作契约 | 郭浩天维护，韦仕学确认 | 识别契约、状态值、错误码、模拟响应、数据字段 | 双端字段与版本对齐 | 韦可不连真实模型完成流程 |
| M1 影像采集 | 韦仕学 | `CaptureSource.capture() -> CaptureResult` | 相机连接、拍摄、取文件、截帧、图片旋转与压缩 | 真机取得本地图片，能预览且记录来源 |
| M2 蛇类识别 | 郭浩天 | `POST /v1/recognitions` 与手动 refresh | HHodata 编码、输出校验、物种映射、预算／去重、超时、密钥 | 先离线验收，再经授权小额验证真实链路 |
| M3 蛇类知识数据 | 郭浩天 | `species.json` 与可用参考图 | 学名／俗名映射、资料来源、不确定性、图片授权 | 仅核验过的映射进入真实候选；其他降为未知 |
| M4 交互与病例卡 | 韦仕学 | App 内「记录伤情」「展示病例卡」入口 | 状态切换、表单、本地保存、候选确认、原图展示 | 接模拟响应走完未咬伤及咬伤两条路径 |
| M5 医院查询 | 韦仕学 | `HospitalDirectory.list(location?)` | 本地数据读取、无定位展示、复制与拨号 | 离线也能查看已存资料，不虚构库存 |
| M6 识别评测与交付支持 | 郭浩天 | 离线测试、受控实景评测、部署说明 | 样本分组、失败统计、调用预算、耗时测量 | 离线测试可重复跑；实景评测需新样本和调用授权 |

**工作量约束：**韦的 Android 工作是关键路径。郭在推理跑通后优先协助数据规范化、测试脚本及联调，不另起训练任务；舒豪杰承担医院来源搜集、参考图授权核对、访谈、界面文案和汇报，不把资料查证都压给韦。

### 实际并行关系

```text
郭：模拟响应／契约 → 真实模型接入 → 物种知识数据 → 部署与评测
                  ↓ 首晚接入同一 Interface
韦：Android壳／相机验证 → 模拟结果驱动页面 → 病例卡／医院 → 真机联调
舒：访谈／医院资料／界面文案 → 调研报告 → PPT／视频／提交
```

两个真正需要切换的 Seam：

- **采集 Seam**：影石采集 Adapter 与本地图片导入 Adapter；后者用于开发和明确标注的演示降级。
- **识别 Seam**：真实 HTTP Adapter 与固定模拟响应 Adapter；模拟模式必须显著标记，正式演示不得把模拟结果当真实识别。

其他逻辑保持简单，不引入通用插件框架、事件总线或多层只转发不处理的封装。

## 4. 先冻结 Interface，双方才能不互相等待

**冻结节点：9/22 17:00。**郭交付响应样例和字段表，韦确认可以用于页面渲染；字段更改需双方同意，不单方面改枚举或重命名。

### 4.1 采集 → 识别

`CaptureResult` 至少包含：

| 字段 | 约定 |
|---|---|
| `captureId` | 一次采集的唯一标识，用来丢弃旧请求结果 |
| `imageUri` | Android 本地 URI，指向可提交识别的 JPEG |
| `originalMediaUri` | 原始照片／视频的本地 URI，仅本地保留 |
| `capturedAt` | 含时区的 ISO 8601 时间 |
| `source` | `insta360` / `phone` / `import`，如实记录来源 |

第一版每次仅提交 1 张图片。视频截帧与选图全部在 M1 内完成，不让郭处理 `.insv`、相机流或 Android URI；郭只接收实际图片字节。

### 4.2 Android → 推理代理

已采用 **Python + FastAPI + HHodata Adapter**。通信细节统一维护在 [识别 Interface v1](contracts/recognition-contract.md)，不再沿用早期的同步多模态模型假设。

本次需要双方同步的变化：

- 单张 JPEG 上限按供应商 2MB 限制保守设为 2,000,000 字节；不再接收 8MiB 图片。图片留存、元数据清理和上传同意按契约执行。
- 上传仍是 `POST /v1/recognitions`；新增 HTTP 202／`pending`，结果查询使用独立的手动 refresh 入口。没有自动轮询或自动重试。
- `resultSource` 区分 `mock` / `live` / `cache`，客户端显著标记。供应商分值单位未明，`score` 保持空值，不生成百分比置信度。
- 所有真实外发尝试先占用持久化预算；默认预算 0。上传和查询均保守计数，同图成功／pending／失败均去重回放。
- 未核验物种映射不进入真实候选；无结果、未知和请求失败不意味着伤者安全。

真实调用的启用条件和 50 次额度安排见 [郭侧 AI 开发执行指南](BoldMaker2026_郭浩天_AI开发执行指南.md)。

### 4.3 郭交给韦的最小包

以下文件已落地，可立即开始零额度联调：

- `contracts/recognition-contract.md`：字段、枚举、HTTP 202、查询、预算和错误约定。
- `contracts/fixtures/` 中的 7 份固定响应：有候选、多个候选、无法判断、无蛇、pending、超时、模型格式错误。
- `data/species.json` 的初版结构；条目待核验，不当作已完成的真实物种库。
- `inference/`：可启动的本地模拟代理。测试采用内存生成图片，不读取或上传现有素材。

韦通过同一个识别 Interface 切换真实／模拟 Adapter，不在每个页面复制模拟逻辑；保持模拟和缓存来源可见。双方不需要等待真实模型可用。

## 5. 数据、病例卡与医疗安全约定

### 5.1 蛇类知识数据：郭负责结构与映射

`species.json` 每条至少包含：`speciesId`、中文名、学名、别名、风险资料、可选参考图、资料来源、核对状态。

- 先覆盖演示涉及的少量物种，不把 188 张素材当成 188 个独立验证样本。
- 观赏品系名不直接当物种名；别名只作辅助，不能作为医疗身份确认。
- 风险资料应允许「未知」及多种毒性作用，不强制二分为“神经毒／血液毒”；未核验资料不展示确定性结论。
- 参考图须标注来源与授权；自行拍摄照片不能自动称为权威标准图。无可用图片就显示“暂无参考图”，不用生成图片冒充。
- 不将“宠物蛇”“未检出蛇”“低置信度”解释为“无毒／无需就医”。

### 5.2 医院数据：舒搜集，韦校验并接入

首版只做**演示所在城市及周边、少量可追溯条目**。建议数据字段：

`hospitalId`、`name`、`address`、`phone`、可选 `latitude/longitude`、`source`、`checkedAt`、`antivenomInfoStatus`、可选 `antivenomNote`。

- `antivenomInfoStatus` 只区分“历史资料提及”和“未知”，不输出“实时有货”。历史资料提及也不意味着适配当前蛇种。
- 统一显示 **“蛇伤救治相关医院信息；接诊及血清情况请电话确认”**，而不是“附近有血清医院”。没有来源则不捏造医院或库存。
- 有坐标且用户同意定位时，使用直线距离排序并明确标记；无定位时提供按城市查看，不编造距离和到达时间。
- 无可靠血清信息时，只能展示有来源的医院联系信息并说明库存未知；不假装满足血清库存查询。
- 打开系统拨号界面，由用户确认拨出；测试时不实际拨打 120 或医院。

### 5.3 病例卡：韦负责本地组装

至少包括：原始图片或视频关键帧、拍摄时间、AI 候选／无法判断、分值单位未确认的说明、可用参考图、用户比对选择、咬伤时间／部位／症状、可选年龄和位置、资料更新时间、医师判断提示。

- 用户选中候选只能记为“用户比对选择”，不能改写成“已确诊”。
- 未提供的伤情字段显示“未提供”；识别失败也允许生成信息卡。
- 有多个候选或未知时不自动选定蛇毒类型、处置方式或抗蛇毒血清。
- 文案定位为 **“辅助记录与信息检索，不用于诊断；疑似蛇咬伤请及时联系急救和就医”**。
- 原资料中关于毒型处理“完全相反”及捆绑导致特定后果的简化断言，未经医学审核不能直接进入产品。

### 5.4 只保留必要的数据与权限

医院和病例卡不依赖后台；选择云模型时，轻量代理仅保护模型凭据、规范化响应，不建设医疗业务后台。

- 模型供应商密钥只放代理环境变量，不写入 APK、Git、日志或视频。
- 公网代理至少使用 HTTPS、演示访问凭证和请求限额；不把供应商密钥作为客户端访问凭证。
- 代理默认不落盘图片、不记录完整请求体；模型供应商的数据保留政策需郭核对，不能承诺第三方绝不留存。
- 上传同意、定位同意分开；用户拒绝上传后仍可记录伤情并查看本地医院。
- 分享病例卡前确认包含的敏感信息；演示使用虚构伤情，不上传真实病人信息。

## 6. 工程归属与协作规则

工程布局（`inference/`、`contracts/` 和初版物种数据已存在；Android、医院数据及正式交付目录仍待实施）：

```text
BoldMaker/
  android/                  # 韦：单一 Android 工程
  inference/                # 郭：推理代理、模型适配、评测脚本
  contracts/                # 郭维护，韦确认：契约与固定响应
  data/
    species.json            # 郭：物种知识
    hospitals.json          # 韦：医院信息，舒提供核验素材
  deliverables/             # APK、视频、PPT、BOM、测试与部署说明
  SDK/                      # 保留原始 SDK 资料
  分类整理/                  # 保留原始素材和备份
```

- Android 沿现有 **Kotlin + XML/ViewBinding** 示例技术栈做最小改造，不为采用 Compose 而迁移。先在原示例验证构建和真机；业务工程再落到 `android/`，保留原始 SDK 归档。
- 仓库由韦负责初始化与集成，郭维护推理目录；公共契约更改需双方确认。本文不自动创建仓库或推送代码。
- 本地数据在打包时复制进 Android assets，不让 App 运行时读取开发机路径。
- 每个文件只有一名主维护人；需要协助时先报文件范围，避免同时编辑同一页面或 Gradle 配置。
- 同一台机器用不同工作目录／worktree，不在共享目录里互相切换分支。
- 每 2–3 小时同步一次：已完成、被什么阻塞、Interface 是否变更。**优先演示可运行结果，不以“代码写完”当验收。**
- 提交不包含模型密钥、真实伤情、原始 SDK 压缩包和全部媒体备份。SDK 是否可重新分发需查许可；仓库保留获取与配置说明。
