# 郭浩天侧｜交给 AI 的开发步骤与注意事项

> 适用对象：继续开发「一拍知蛇」AI 识别、数据映射和推理部署的编程 AI。
> 先使用已落地的骨架完成离线联调，再申请少量真实调用。不要重新从零生成工程，也不要修改韦仕学负责的 Android／相机代码。

## 0. 先明确本轮状态与硬约束

**已落地：**FastAPI 代理、HHodata 单次上传／单次查询 Adapter、7 组模拟响应、图片校验与元数据清理、持久化调用账本、同图去重、离线测试；蛇类使用已确认的爬行类别 `class=R`。**已实测：**一张整图的真实上传、结果查询与同图缓存；测试时供应商有候选但本地映射缺失；现已按郭核验结果补齐颈棱蛇并通过离线回归，详见第 7 节。**未完成：**真实场景评测、完整物种知识库、Android 真机联调和公网部署。

1. 模型拟用 HHodata，接口事实以 [识别契约](contracts/recognition-contract.md) 汇总的本地规范及郭补充的供应商资料为准。此前“大模型提示词选型／默认百炼”的安排已被替代；目前不使用百炼作为自动兜底。
2. 郭于 **2026-09-22 确认剩余 50 次**，这是用户提供的当时余额，不是代理实时查询结果，也不是本轮调用授权。默认 `mock`，真实调用预算默认 0；单元测试、启动和健康检查不得请求供应商。
3. **现有 `分类整理/` 图片在特殊场地拍摄，明显比实际抓拍清晰，只能做开发流程测试。**不能据此报告实际场景准确率；人为加噪、模糊也只能叫合成鲁棒性检查。实景评测等待郭提供新样本。
4. 密钥只在进程环境变量中配置，源码和 APK 不读取 `api/*.txt`。当前实现没有读取、复制或输出这些凭据。
5. 识别只给候选和不确定性，不自动生成医疗诊断、血清用法或处置建议。模型分值的含义尚未确认，保留原值但不给百分比解释。

## 1. 恢复上下文，确认归属

按这个顺序阅读：

1. 本指南。
2. 涉及 Android 对接／响应字段时，读 [识别 Interface](contracts/recognition-contract.md)；它是通信约定的唯一维护位置。
3. 修改推理行为时，读 `inference/app.py`、`provider.py`、`budget.py` 及相关测试。
4. 需要了解比赛和其他成员安排时，再读 [模块化并行规划](BoldMaker2026_模块化并行开发规划.md)。

郭侧可修改 `inference/`、`contracts/`、`data/species.json` 和本指南；修改公共 Interface 前通知韦。保留 SDK 原归档、已有素材与 `分类整理/备份勿动/`，不初始化／推送远程仓库或部署共享资源，除非本轮得到明确授权。

**完成标准：**确认当前已有文件和他人的在途修改，列出此次要改的郭侧文件；不把已有实现重写一遍。

## 2. 先运行不消耗额度的开发闭环

以下命令均从 `E:\BoldMaker` 根目录执行，使用 Git Bash。项目使用 Python 3.12；需要隔离环境时先创建并激活 `.venv`，再安装依赖。

```bash
python -m venv .venv
source .venv/Scripts/activate
python -m pip install -r inference/requirements.txt
RECOGNITION_MODE=mock LIVE_CALL_LIMIT=0 python -B -m unittest discover -s inference/tests -v
```

已经有可用环境时不重复创建或安装。这里使用标准库 unittest，无需另装 pytest。测试通过 HTTPX MockTransport 或假 Adapter 截断供应商请求，并以临时 SQLite 目录测预算；不要把测试改成真实模型调用。

启动命令、场景头和响应格式见契约第 5 节。先将 7 种结果交给韦：单候选、多候选、不确定、无蛇、pending、超时、输出格式错误。Android 必须显著标记模拟来源，识别失败或 pending 不阻断伤情记录。

**完成标准：**所有离线测试通过；本地 HTTP 逐一返回约定状态码；健康检查显示 mock、0 次本地真实调用；Android 开发不需要真实密钥。

## 3. 先消除文档缺口，再启用真实识别

已确认的类别、覆盖数量口径和查询建议见契约第 6 节：蛇类使用 `class=R`；配额查询免费，但不能据此推断识别结果查询免费。爬行类总覆盖数不等于蛇类数量，也不证明目标蛇种的识别效果。

仍需向供应商或郭核实：

- 本次目标蛇种是否在识别覆盖范围内。
- 识别结果查询、上传失败和超时是否扣次数。
- 图像候选首列数值的范围、单位和校准含义。
- 图片保留、使用授权与隐私条件。

郭已提供当时余额，无需为本轮配置更新再发请求。后续经授权可单独使用免费的 `quota=1` 核对最新余额；当前代理未实现配额查询，也不在启动或健康检查时自动查询。百科查询和识别结果查询的扣费规则分别核实，不靠试错消耗额度。

**完成标准：**保存尚缺事项的可追溯说明；启用前确认可用凭据、样本上传同意和本次允许的外发上限。结果查询计费未明时仍按每次外发预占预算。条件不足就继续模拟联调，不宣称模型已接通。

## 4. 整理实景样本与最小物种映射

收到新图片后先离线登记：文件路径、来源和授权、拍摄环境、真实／受控／合成类型、标签及核验人、距离、光照、遮挡／模糊、是否同一个体或连拍组。

- `development_only`：现有受控场地照片，只测试读取、上传编码、元数据清理和界面。
- `field_candidate`：新找到但尚未核验来源或标签的现场照片，不计入正式指标。
- `field_verified`：来源许可和标签已核验的实际抓拍，可用于小样本评测。
- `synthetic_robustness`：人为降质图片，单列结果，不替代实景证据。

先挑选少量符合实际使用条件的样本及非蛇负例，避免同一个体的连拍重复计数；有疑义的标签保留未知，不硬凑正确答案。不要为了拍素材接近、挑逗或捕捉危险蛇类。

`data/species.json` 已有按郭核验结果录入的颈棱蛇映射；玉米蛇和加州王蛇仍为待核对开发条目。**真实 Adapter 仅使用 `verificationStatus="verified"` 的映射**；已录入的“伪腹蛇”保留用户原文，并在来源中注明，不据此声称已独立核验别名拼写。补充映射须核对名称、学名与来源；毒性资料和参考图授权另行核验，颈棱蛇的风险状态仍为 unknown。

**完成标准：**得到可追溯的新实景样本清单和本次需用的已核验名称映射。缺少实景样本时，写“实景效果尚未评估”，不拿原有 188 张照片替代。

## 5. 受控启用：每次调用都有目的和预算

`.env.example` 仅列配置项，**程序不会自动加载 `.env`**。通过当前进程环境或部署平台的 Secret 注入：

- `RECOGNITION_MODE=hhodata`。
- `HHODATA_API_KEY`：供应商密钥；只配置，不输出。
- `HHODATA_CLASS=R`：已确认的爬行类别，也是项目默认值；不是供应商的默认 B。
- `PROXY_TOKEN`：另生成至少 16 字符的代理访问凭证，不复用供应商密钥。
- `LIVE_CALL_LIMIT`：本地账本的累计尝试上限，允许 0–50，默认 0，首次建议先批准 1 次。
- `LIVE_LEDGER_PATH`：固定持久化账本路径；本地默认 `.runtime/hhodata.sqlite3`。

先用**本地健康检查**确认配置和预算；如需更新账号余额，按步骤 3 单独核对。上传前取得图片发送给第三方的同意。首次只发 1 张已确认许可和用途的图片；若返回 pending，再确认预算后进行一次手动查询，不连续点击或自动轮询。

### 预算管理规则

- 每个上传或识别结果查询的外发 HTTP 尝试先占 1 次本地预算；网络失败／超时不退款。这是保守保护，不代表供应商真实扣费规则，也不是对免费配额查询的计费声明。
- 重启不会清零；提升上限是调整**累计上限**，不是另获一批免费次数。始终与供应商剩余额度对照。
- 同类别、同一规范化图片命中账本，不随 requestId 改变而重新调用。成功、pending 和失败均可回放；客户端必须显示 `resultSource=cache`。
- 超时或崩溃可能已经在供应商侧执行，遇到此情况先人工核查。不要删除账本、换一个账本路径、改图或改类别来绕过去重和额度保护。
- 当前没有“强制重试”入口。如果确需重试失败图片，先由郭确认可能重复扣费，再设计明确、受预算约束的恢复步骤。

按郭确认的当时剩余 50 次，可参考如下保守分配；后续按最新余额调整，不是本轮自动获批的调用额度：

| 用途 | 外发尝试预算 |
|---|---:|
| 首次接通，含少量手动查询 | 最多 3 |
| Android 真实联调 | 最多 5 |
| 新实景小样本评测，含查询 | 最多 12 |
| 现场演示与异常预留 | 至少保留 30 |

**完成标准：**每批开始前明确最大外发次数、图片、问题和停止条件；结束后记录本地账本差额、供应商可确认的扣费情况、识别状态和耗时，不只记录成功例。遇到配额错误、未知响应或网络异常即停止本批，不自动切到另一模型。

## 6. 接入韦的 Android，再考虑部署

先交给韦的内容已经存在：`contracts/recognition-contract.md`、`contracts/fixtures/`、`data/species.json`。先使用 mock 代理或本地 fixtures，之后只替换识别 Adapter。

联调重点：2MB 限制、上传同意、代理鉴权、HTTP 202、手动 refresh、超时、未知物种、缓存来源、旧 requestId 不覆盖新采集。手机连相机 Wi-Fi 后是否还能请求云端，必须真机验证，不能以电脑测试代替。

部署前单独取得共享资源／公网发布授权；使用 HTTPS、受控访问凭证和一份固定持久化账本。不要部署多个独立账本的副本，也不要使用重启就丢失账本的临时磁盘。代理不保存图片和伤情；供应商是否留存图片按步骤 3 的实际说明告知用户。

**完成标准：**同一台 Android 真机走通真实影石影像 → 真实响应或如实不确定 → 信息卡／医院入口；保存实测证据，并分别记录未实现的快捷键、网络切换等限制。模型分类测试不等于医疗安全验证。

## 7. 本轮收尾格式

向郭汇报：改动文件、离线测试结果、真实外发次数、本地累计预算、仍未知的供应商事项、下一步是否需要郭确认。区分“模拟通过”“编码符合本地规范”“供应商实测通过”“实景效果已验证”，不能相互替代。

创建骨架及同步类别配置时未调用供应商；2026-09-22 经郭授权对 `测试图片/人工伪蝮蛇.jpg` 做了一次真实整图测试，累计 **1 次上传＋1 次结果查询，配额查询 0 次**，持久账本计数为 2。此前剩余 50 次由郭确认，测试后实际余额未查询，不能据此声称剩余 48 次或 49 次。

### 首次真实整图测试记录

- 输入：1280×2772，原文件 964609 字节；规范化后 309331 字节，保留黑边和播放器控件，未裁剪或缩放。它是饲养箱视频截图，仅用于流程联调；文件名不是已核验标签。
- `class=R`，上传用通用文件名 `capture.jpg`，不向模型提供文件名中的蛇名。上传返回供应商业务码 1000、代理 HTTP 202；单次上游等待 171ms。
- 一次显式结果查询返回业务码 1000，检测框 `[573,814,1228,1470]`，候选依次为 `[97.6,"颈棱蛇|Red Keelback|Pseudagkistrodon rudis",9316,"R"]` 和 `[0.38,"|Moorish Viper|Daboia mauritanica",11437,"R"]`；分值保持原始数值，不解释为准确率。查询单次上游等待 318ms，以上耗时不含人工间隔，不是端到端识别耗时。
- 当时代理返回 HTTP 200、`status=uncertain`、空候选，原因是本地没有对应的已核验物种映射，不是供应商无候选；测试当时尚未取得图片物种的人工核验。
- 同图换 requestId 后，在禁止网络且本地预算为 0 的条件下回放 `resultSource=cache`；账本仍为 2。查询脚本的一次本地语法错误发生在执行前，没有产生额外外发请求。
- 后续郭确认图片物种为颈棱蛇，并提供别名“伪腹蛇”。已将该名称映射标为 verified，其他两个开发条目仍为 pending_review，风险资料保持 unknown；此单张受控样本的核验不代表实景总体准确率。
- 补映射后用已记录响应离线重放，候选列表包含颈棱蛇、原始分值 97.6；因次候选 Daboia mauritanica 未入库，状态仍为 uncertain。单独返回颈棱蛇及其已录入别名时可得到 candidates 状态，48 项离线测试全部通过，未新增真实调用。
- 项目默认仍为 mock／预算 0；`.runtime/hhodata.sqlite3` 内容与计数均未改动。该旧缓存不会因物种表更新自动重算，仍回放原空候选；用已记录响应验证新映射，不清账本或重传同图。
