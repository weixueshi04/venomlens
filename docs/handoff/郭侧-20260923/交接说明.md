## 2. 40 秒比赛演示

交付包根目录执行 `python 启动演示.py`，或：

```bash
python -B -m http.server 8766 --bind 127.0.0.1 --directory 演示
```

打开 `http://127.0.0.1:8766`。不要直接双击 HTML，浏览器会限制本地 JSON 读取。

推荐顺序：已有照片预览 → 单候选参考卡 → 放大图片 → pending 后手动查询 → 指出失败也能查看求助提醒。“单独查看物种卡设计”可以演示猪鼻蛇，但必须保留“不是识别结果”的标记。

本页只读取本机 fixtures。照片留在浏览器，不上传、不保存，不调用识别代理；不选照片也可演示固定响应。百科链接只有主动点击才联网，核心卡片无需外网。本页不是 APK，也不是对所选照片的真实识别。

## 3. 韦侧接入：直接读取卡片投影

识别仍以 `contracts/recognition-contract.md` 为准。取得 `candidates[].speciesId` 后，查导出的 `species-cards.json`；不改识别响应，不重复调用模型。

源码根目录导出（输出必须是一个新的空目录）：

```bash
RECOGNITION_MODE=mock LIVE_CALL_LIMIT=0 python -B -m inference.cards --output ./card-export
```

导出格式 `cardSchemaVersion="1"`：
- `normal[speciesId]`：正常展示投影，未审文案与图片已移除，名称未核验则给占位文字。
- `preview[speciesId]`：仅用于 mock/独立设计预览的草稿，必须显著标记；不要用于真实识别结果页。
- `safety`：固定通用提醒，不按候选生成毒性、用药或处置建议。
- `mode="mock" / liveCallsEnabled=false`：说明该演示包的性质，不是代理实时配置或供应商余额。

每张卡含 `nameStatus/contentStatus/previewOnly/hook/checklist/lookAlikes/images/externalRefs/riskStatus/safety/notice`。Android 可直接使用投影；若自行读取原始 species.json，须实现相同规则：

1. `verificationStatus` 只审核名称；文案读取 `comparisonProfile.reviewStatus`，图片读取各自 `reviewStatus`。
2. 文案/图片只有 `reviewStatus="verified"` 且有 `reviewedBy`、`reviewedAt` 才算完成审核；名称也必须 verified 才进入正常卡片。当前未审状态须保留。
3. 演示允许显示待审文案与允许的演示图，标“演示草稿”；不能把 `demoDraft` 缺失或名称已核验当作整卡已审。
4. 图片还需 `sourceStatus` 为 `team_declared` 或 `record_matched`，并有 `rights/source`。来源未闭合的图片连演示包也不进入。
5. 不直接展示未审 `techNotes`，不采用各物种草稿生成医疗建议；通用提醒独立显示。pending、超时、拒绝上传或无候选均不阻断求助。
6. `file` 是发布图相对路径，复制至 assets 并保留目录；显示图片说明、署名/权利声明、来源、修改说明及已核对的来源链接。
7. `uncertain` 可有候选；缺卡/缺图提示资料待核验，不显示“安全”。`resultSource` 仍取识别响应，不把卡片设计预览叫作 live。

完成标准：7 场景、手动查询、旧响应隔离、草稿标识、缺图兜底与独立求助入口均可操作。Android 接入与真机验收仍由韦完成。
