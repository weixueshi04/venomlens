## 2. 产品定义

### 2.1 增量范围（Scope）

**本次只改"视觉与交互层"，不改"功能与语义层"。**

✅ **可改动**
- `cards.css`：配色、字号、间距、圆角、阴影、组件样式、响应式、无障碍样式（全部可重写）。
- `index.html`：DOM 结构、区块顺序、静态文案的**呈现方式与语气**（在不改变合规语义的前提下）、`aria-*` 属性、无障碍标记。
- `cards.js`：**仅与视觉/交互相关的行为**——渲染 DOM 时增补的 class、`aria` 属性、安抚性微交互、`prefers-reduced-motion` 判断、帮助入口的滚动/聚焦逻辑。

❌ **不可改动（硬约束）**
- **功能逻辑**：7 种模拟场景、pending 手动查询、图片校验（JPEG / 2 MB / 尺寸）、审核开关、缺卡/缺图兜底、`fetch` 数据流、`safeLink` 的 HTTPS-only 白名单校验、图片路径 `/data/card_images/` 校验。
- **安全文案语义**：`SAFETY` 三条、免责句、"候选不是结论""未检测到蛇不代表安全""风险：未知"等**语义不得弱化、删除或改写成更轻描淡写的表达**。可以调整语气与排版让其更易读，但**不能改变其安全含义**。
- **数据契约**：`species-cards.json` 结构（`cardSchemaVersion="1"`、`mode`、`liveCallsEnabled`、`normal`/`preview` 投影、卡片字段 `commonName`/`nameStatus`/`contentStatus`/`images[]`/`notice`/`hook`/`checklist`/`lookAlikes`/`externalRefs` 等）**一个字段都不能动**。`cards.js` 对这些字段的读取路径保持不变。
- **CSP**：`default-src 'self'`，不引入外部字体 / CDN / 图标库 / 网络图片。
- **MOCK 合规红线**：所有模拟界面保留 MOCK 标注、免责文案、审核状态徽章、参考图署名。

> 一句话：**换皮肤、理层级、调语气，不动骨头、不改契约、不碰安全语义。**

### 2.2 Product Goals（3 个正交目标）

1. **急救优先（Calm-first）**：让"被咬伤后现在该做什么"成为**页面任何状态下都零滚动可见、可一键触达**的稳定锚点，而不是埋在侧栏底部的按钮。
2. **降认知负载（Low-load）**：在恐慌/手抖/强光/单手场景下，信息**分层呈现**——先"该做什么"，后"这是什么蛇"，用大字号、高对比、大触控目标让用户一眼抓到重点。
3. **公益关爱气质（Caring, not clinical）**：用配色、圆角、文案语气传递"有人在帮你"的温暖与平静，既**避免医疗冰冷感**，也**避免过度可爱**削弱严肃性与可信度。

### 2.3 User Stories

| # | 角色 | 故事 | 收益 |
|---|---|---|---|
| US-1 | 刚被蛇咬伤的用户（手抖、心慌、注意力窄化） | 作为刚被咬伤的用户，我希望**一眼看到"现在该做什么"**，而不是先读懂蛇的名字 | 恐慌中无需阅读长文即可抓到求助/急救动作 |
| US-2 | 被咬伤、极度紧张的用户 | 作为紧张的用户，我希望**任何时候都能一键找到"已被咬伤？求助"入口**，不用滚动、不用先操作识别 | 求助锚点始终在视野内（顶部常驻），降低"找不到"的二次恐慌 |
| US-3 | 户外强光下、单手操作的用户 | 作为户外用户，我希望**字够大、对比够高、按钮够大**，一只手也能点中 | 强光/手抖/单手场景仍可读可点 |
| US-4 | 见到蛇但未受伤、想辨认的用户 | 作为想辨认蛇种的用户，我希望**先看到安全提示、再看候选蛇种**，且清楚知道"候选不是结论" | 避免为辨认而冒险靠近，理解不确定性 |
| US-5 | 比赛评委（3 分钟快速理解） | 作为评委，我希望**打开页面 5 秒内 get 到"这是救助工具、不是识别玩具"** | 快速理解产品理念与公益定位、判断完成度 |
| US-6 | 需要安抚情绪的用户 | 作为恐慌中的用户，我希望页面**用平静、有人情味的语气和我说话**（如"别急，我们一步步来"），而不是冷冰冰的报错 | 情绪被接住，减少慌乱导致的错误决策 |

## 4. 约束（Constraints）

- **纯离线**：CSP `default-src 'self'`；**无外部字体、无 CDN、无图标库、无网络图片**。图标仅用内联 SVG / Unicode。
- **不新增依赖**：无 npm、无构建工具、无框架。仍是三文件（html/css/js）静态产物，兼容 `export_bundle` 的 `shutil.copy2` 打包流程。
- **移动优先响应式**：先设计窄屏，再向宽屏增强。
- **无障碍**：`aria-*`、`:focus-visible`、`prefers-reduced-motion`、语义化标题、对比度 AA。
- **数据契约冻结**：`species-cards.json` 字段、`cards.js` 的读取路径、`safeLink` 白名单、图片路径校验**保持不变**。
- **合规语义冻结**：`SAFETY`、免责、徽章、署名、诊断声明的**语义不得弱化**（呈现方式可调）。
- **可回灌性**：本次产出的设计原则（配色、字号、触控、分层、语气）应抽象为**可迁移到 Android App** 的设计语言（见 §5.5），但本次只落地 Web 演示页。

## 5. UI 设计稿（文字 + 结构描述）

### 5.1 新布局结构（信息动线：急救 → 状态 → 卡片 → 底线）

```
┌──────────────────────────────────────────────────────────┐
│ [顶部栏] 一拍知蛇 · 公益标识        [MOCK 本机离线演示徽章]  │  ← 品牌弱化，MOCK 常驻
├──────────────────────────────────────────────────────────┤
│ ★ 求助锚点条（常驻 / sticky）                              │  ← P0-1 最高优先级
│   「如果已被咬伤 → 别急，点这里看该做什么」 [大号求助按钮]     │     任意状态可见、零滚动可达
├──────────────────────────────────────────────────────────┤
│ [首屏引导 + 空状态安抚]  平静的一句话 + 引导（不选图也能演示） │  ← P1-1
│                                                            │
│  ┌───────────┐  ┌──────────────────────────────────────┐  │
│  │ 左：操作面板 │  │ 右：结果区（aria-live）               │  │
│  │ · 你的照片   │  │  ① 当前状态一句话（该做什么/这是啥）    │  │  ← P0-2 状态优先
│  │ · 场景选择   │  │  ② 物种卡（次要，可折叠次级信息）       │  │  ← P1-3
│  │ · 审核开关   │  │  ③ 卡片级安全声明                      │  │
│  │ · 单独看卡   │  │  ④ #safety 安全底线（视觉强锚，常驻）   │  ← P0-2 上移/增强
│  └───────────┘  └──────────────────────────────────────┘  │
├──────────────────────────────────────────────────────────┤
│ [页脚] 合规声明 · 名称核验≠文案审核≠照片核验 · 数据契约说明   │
└──────────────────────────────────────────────────────────┘
   移动端：单列，求助锚点条吸顶，操作面板折叠在结果区之上/之下
```

**关键变化 vs 现状**：
1. `#help` 按钮 **从左侧栏底部（`aside` 内）移出**，升级为**贯穿页面的常驻求助锚点条**（紧贴顶部栏下方，或 sticky 吸顶），移动端吸顶。
2. `#safety` 安全区块 **视觉权重提升**（当前在结果列最底部，易被长物种卡推到视野外）——增强边框/底色/图标锚，并在物种卡很长时仍保证用户能感知其存在（如求助锚点条始终指向它）。
3. 结果区信息顺序：**状态一句话 → 物种卡 → 安全声明**，而非当前的"标题 → note → 卡片 → 底部 safety"平铺。

### 5.2 配色方向（两个候选 + 推荐）

> 两套均已实测通过 **WCAG AA**（正文对比度 ≥4.5:1，大字/图标 ≥3:1）。色值为建议基线，架构师可微调但需复核对比例。

#### 候选 A：晨雾浅色安抚系（Light · Calm Mist）— ✅ **推荐**

以柔和的雾白/浅苔绿为底，深墨绿为主文字，暖陶土色为"关爱/求助"点缀，柠檬绿保留为品牌记忆点但**降级为小面积强调**（不再大面积铺陈）。

| Token | 色值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--bg` | `#F5F7F2` | 页面底 | — |
| `--surface` | `#FFFFFF` | 卡片/面板底 | — |
| `--surface-2` | `#EDF1E9` | 次级面板/代码底 | — |
| `--text` | `#1C2B24` | 主文字 | 14.8:1 ✓ |
| `--muted` | `#4E6157` | 次要文字 | 6.6:1 ✓ |
| `--action` | `#1F6B4A` | 主行动色（深松绿，守护感） | 6.4:1 ✓ |
| `--action-soft` | `#E3EFE6` | 行动区浅底 | 文字 12.5:1 ✓ |
| `--care` | `#A34A26` | **求助/关爱暖陶土色**（温暖不刺眼） | 5.9:1 ✓ |
| `--care-soft` | `#FBEDE4` | 求助区浅底 | 文字 12.9:1 ✓ |
| `--verified` | `#2F7D53` | 已核验徽章 | 5.0:1 ✓ |
| `--pending` | `#8A5A12` | 待核验徽章（暖褐，非报警红） | 5.9:1 ✓ |
| `--neutral` | `#5E6E63` | 中性/风险未知徽章 | 5.4:1 ✓ |
| `--mock` | `#2A3A32` | MOCK 徽章底（白字 12:1） | — |
| `--line` | `#C9D3C6` | 分隔线/边框 | — |
| `--lime` | `#D2F56A` | **品牌记忆点**，仅小面积点缀 | 装饰用，不承载正文 |

**气质**：清晨薄雾中的林地，安静、干净、有人守护。浅色底在**户外强光下可读性最佳**（深色底在强光下反光、对比骤降），这正是被咬伤用户的真实场景。**这是推荐 A 的决定性理由。**

#### 候选 B：暖夜深色守护系（Dark · Warm Vigil）

保留深色基因（夜间/暗光友好），但把当前的"酸性柠檬绿+冷墨绿"调暖：底色带一点暖调，强调色柔化，求助区用暖琥珀而非冷绿。

| Token | 色值 | 用途 | 实测对比度 |
|---|---|---|---|
| `--bg` | `#16211C` | 页面底（暖墨绿） | — |
| `--surface` | `#20302A` | 面板/卡片底 | — |
| `--surface-2` | `#1A2822` | 次级面板 | — |
| `--text` | `#F2F5EE` | 主文字 | 12.6:1 ✓ |
| `--muted` | `#AFC0B4` | 次要文字 | 7.3:1 ✓ |
| `--action` | `#CDE97A` | 主行动色（柔化柠檬绿） | 10.2:1 ✓ |
| `--care` | `#F0A870` | **求助暖琥珀** | 7.0:1 ✓ |
| `--care-soft` | `#3A2A1E` | 求助区底 | 文字 12.5:1 ✓ |
| `--verified` | `#8FD6A6` | 已核验徽章 | 8.1:1 ✓ |
| `--pending` | `#E8C07A` | 待核验徽章 | 8.1:1 ✓ |
| `--neutral` | `#9FB0A5` | 中性徽章 | 6.1:1 ✓ |
| `--mock` | `#0C1411` | MOCK 徽章底（白字 18.7:1） | — |
| `--line` | `#3A4C42` | 边框 | — |

**气质**：夜里陪你值守的一盏暖灯。夜间/暗光友好，但**户外强光下不如浅色**。

#### 🏆 推荐：**候选 A（晨雾浅色安抚系）**

理由：
1. **强光可读性**——被咬伤/见到蛇的用户多在户外白天，浅色底 + 高对比文字在阳光直射下可读性远优于深色底（深色底反光、对比塌陷）。这是安全性考量，不只是审美。
2. **公益/关爱气质**——浅色雾绿 + 暖陶土天然传递"平静、干净、有人照顾"的感觉，比深色+柠檬绿的"科技/极客"观感更贴合救助工具定位。
3. **去酸性**——当前柠檬绿 `#d2f56a` 大面积使用偏"能量饮料/科技风"，与"安抚恐慌用户"的目标相悖；A 方案将其降级为小面积品牌记忆点。
4. **合规元素更清爽**——浅色底下，审核徽章/署名/免责文案更容易做出"有秩序的层级"而非"深色底上的刺眼色块"。

> 若团队坚持保留深色基因，可选 B；或按 P2-2 做 A 为默认 + B 为夜间切换。**产品经理推荐 A 为默认。**

### 5.3 字体排印策略（仅系统字体栈，无外部字体）

```css
font-family: system-ui, -apple-system, "Segoe UI", "Microsoft YaHei",
             "PingFang SC", "Hiragino Sans GB", sans-serif;
```

| 层级 | 字号（移动 → 桌面，`clamp()`） | 字重 | 用途 |
|---|---|---|---|
| 求助锚点主文案 | `clamp(18px, 4.5vw, 22px)` | 700–800 | "如果已被咬伤…" |
| 求助按钮 | `clamp(17px, 4vw, 20px)` | 700 | 大号、易点 |
| 页面主标题 H1 | `clamp(26px, 5vw, 40px)` | 800 | 首屏理念句（比当前略收敛，把视觉预算让给求助） |
| 状态一句话 H2 | `clamp(19px, 4vw, 24px)` | 700 | "候选不是结论"等 |
| 物种名 H3 | `clamp(22px, 5vw, 28px)` | 800 | 卡内蛇名 |
| **正文基准** | **≥16px**（当前 15px，P0-4 提升） | 400–500 | 说明/检查项 |
| 次要/署名 | ≥13px（不低于 12px） | 400 | 免责、图片署名、requestId |

- **行高**：正文 1.6–1.75（恐慌用户需要更松的行距降低阅读压力）；标题 1.25–1.4。
- **字间距**：中文标题可轻微收紧（-0.5px），正文默认。
- **禁止**：不使用 `<12px` 的字号承载任何合规/安全信息；不用纯细体（<400）承载求助文案。

### 5.4 关键组件样式

**① 求助锚点条（P0-1，本次灵魂组件）**
- 位置：顶部栏正下方，**sticky 吸顶**（移动端同样吸顶），z-index 高于内容。
- 样式：`--care-soft` 暖底 + `--care` 左边框（4–6px 竖条，形成"守护"视觉锚）+ 内联 SVG 心形/十字图标（非 emoji，避免风格失控）。
- 按钮：≥48px 高、≥44px 触控、`--care` 实心或描边，圆角 10–12px，hover/active/focus 有明确反馈。
- 文案：安抚式，如"**如果已被咬伤，别急 → 点这里看现在该做什么**"（语义仍指向 `#safety`，不新增医疗建议）。
- 行为：点击 → 滚动到 `#safety` 并 `focus()`（复用现有逻辑），但**滚动行为受 `prefers-reduced-motion` 控制**（reduce 时用 `auto` 而非 `smooth`）。

**② 安全底线区块 `#safety`（P0-2）**
- 视觉权重提升：`--care-soft`/暖底 + 明显边框 + 顶部图标，`scroll-margin` 保证锚点定位不被吸顶条遮挡。
- 三条 `SAFETY` 用**带序号/图标的列表**呈现，每条一行、大字号、易扫读。
- 保留"不提供诊断、用药或血清建议；本演示不提供医院实时库存"声明。

**③ 物种卡 `.species-card`（P1-3）**
- 从当前"深色页面上的浅色纸卡"改为与新体系统一的 `--surface` 卡片 + 柔和阴影（`box-shadow` 极淡，避免拟物厚重）。
- 卡内层级：**蛇名（大）→ 审核徽章组（统一样式）→ notice（暖色左边框提示条）→ hook 观察要点（醒目）→ checklist（大字号、带勾选图标）→ 参考图画廊 → 折叠的易混说明/外链/署名（`<details>` 默认收起）→ 底部"不生成诊断"声明条**。
- 参考图署名（rights/source/modification/sourcePage）保留，但排为**统一的小字信息块**，视觉克制、不喧宾夺主。
- 缺卡/缺图兜底文案保留，样式统一为"平静的提示"而非"报错"。

**④ 审核状态徽章（P1-4）**
- 统一 pill 样式：verified=`--verified`、pending=`--pending`、unavailable/风险未知=`--neutral`、演示草稿=暖褐 draft。
- **色觉障碍冗余**：颜色 + 文字（"名称已核验"/"名称待核验"），不单靠颜色区分。
- MOCK 徽章：`--mock` 深底白字，常驻顶部栏，醒目但不报警化。

**⑤ 场景选择器 `<select>`（P1-2）**
- 大号、易点（≥44px 高），选项文案在不改 value 前提下更易读，下方一行微说明当前场景含义（仍标注 MOCK）。

**⑥ 空状态 `.empty`（P1-1）**
- 从"设计说明口吻"改为"引导 + 安抚"：一个平静的内联 SVG（如远山/叶子/守护盾，**不用蛇的恐怖形象**）+ 引导文案（"不选照片也能演示；求助提醒随时可看"）。
- 虚线边框柔化，底色用 `--surface-2`，避免"报错感"。

**⑦ 图片放大 `dialog`（P1-6）**
- 与新体系统一；关闭按钮 ≥44px；署名清晰；保留"仅比对已有照片，不要接近蛇确认细节"。

### 5.5 可回灌 Android 的设计原则（本次产出，供后续迁移）

1. **急救锚点常驻**：App 端同样应有"始终可见的求助入口"，不埋在导航深处。
2. **信息分层动线**：先"该做什么"，后"这是什么"。
3. **配色令牌化**：`--care`（求助暖色）、`--action`（守护绿）、`--verified/pending/neutral`（审核色）作为跨端 design tokens。
4. **触控 ≥44dp、正文 ≥16sp、对比 AA**：与 Android 无障碍规范一致。
5. **语气**：温暖、平静、不恐吓、不轻描淡写——文案风格跨端统一。
